Augmented Vertex Block Descent using CUDA

Johnny Zhang

Webpage: https://johnnyanliz.github.io/avbd-on-gpu

Summary

I will implement an Augmented Vertex Block Descent (AVBD) solver on the GPU for simulating rigid bodies, then I will attempt further optimizations based on experiments.

Background

I will implement a 3D rigid-body simulation in CUDA using Augmented Vertex Block Descent (AVBD). The simulation will model boxes that fall, collide, and stack under gravity. At each timestep, collision detection identifies potential colliding pairs and computes contact points and normals for those pairs. The paper uses DirectX 11 compute shaders. CUDA interoperates with Vulkan, so I can test AVBD on its own and in a real-time graphics application.

Parallelization is crucial and complicated in solving such simulation problems in real-time applications due to the sheer number of bodies and the potential interactions between those bodies. AVBD’s approach scales well and has good accuracy with its local primal-dual approach.

I will follow the paper’s graph-colored schedule. Bodies connected by a contact are assigned different colors. Bodies of the same color can update in parallel because each writes its own pose while its neighbors’ poses stay fixed during that pass. The colors run in sequence so later passes can read earlier updates. After all colors finish, contacts can update their force estimates and stiffnesses in parallel because each contact reads body poses and writes its own state.

Challenge

As mentioned in the paper, dependencies exist between colors assigned to the bodies. Each color gets updated in a global pass before the next color starts. If a warp updates 32 bodies of the same color and their contact counts differ substantially, the contact loop runs as long as the busiest lane needs. I want to investigate how the choices I make in coloring the graph can lead to better work distribution.

Another potential approach is to separate the problem into islands, or groups of connected bodies. A CUDA block can go through the colors in one island independently of the blocks processing other islands. Packing each island’s data into shared memory could also improve locality and reduce memory traffic.

Another area that has potential for improvement is collision detection. As mentioned in the paper, collision detection can take longer than the solver for scenes with many bodies.

Goals and Deliverables

Plan to achieve

I will implement a working CUDA AVBD solver for 3D boxes that fall, collide, and stack. I will use the paper’s graph-colored schedule as the GPU baseline and validate it on small scenes, such as a box dropping onto a floor and a stack settling under gravity.

I will compare the baseline with a schedule that groups bodies within each color by their number of contacts. This keeps the coloring fixed and tests whether assigning bodies with similar workloads to the same warp reduces idle lanes.

I will benchmark separate stacks, dense piles, and collapsing towers. I will measure collision detection, coloring and scheduling, and solver time separately. I will compare runtime at a fixed iteration count and check how quickly each schedule reduces penetration.

Hope to achieve

I will try finding simulation islands and assigning them to CUDA blocks. I will test whether the reduction in kernel launches and global-memory traffic offsets the cost of finding and packing islands.

My stretch performance goal is to simulate 100,000 rigid bodies at 60 fps on my NVIDIA RTX 3060.
